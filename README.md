## 重点功能说明

### 出港排班表（`/schedule/`）

- 上传 Excel，自动筛选出港航班（航班号自动清理 `#`、`&`）
- 计离 **0830 之前** 的航班自动剔除（属于前一组）
- 按计离自动分三段，分页切换查看：
  - 🌅 早上 `0830–1400`
  - ☀️ 下午 `1400–1830`
  - 🌙 晚上 `1830` 以后
- 备注列自动组合，顺序固定：**预推时间 → 特服（出港） → 航班调时**
- 负责栏多选（预设 5 人 + 自定义），导出图片用鲜艳实色标签直观区分
- 每行可「插入 / 删除」；插入的空行可直接编辑
- 登机口默认预填 `2`，只需补后两位
- 草稿：`存草稿` / `读取草稿` / `清空草稿`（存于浏览器 localStorage）
- 导出：当前页 Excel、全部 Excel（早 / 午 / 晚 三段各一表）、导出图片（灰白配色表头、负责人彩标）
- `一键清空` 整张表（带确认）

### KN航班出港统计（`/kn-stats/`）

- 上传 FIOS 系统导出的 Excel（.xls / .xlsx）
- 仅保留**出港**且航班号以 **KN** 开头的航班；删除机号为 `CNL` / `DEL` 的取消航班；自动清理航班号中的 `#`、`&`
- 在「计飞」右侧插入**截载时间**列（计飞 − 35 分钟）
- **出港订座** = 三舱位数相加（如 `0|0|158` → 158）
- 计飞 **1030（含）之前** 为早始发，在分界处插入汇总行「早始发人数：X」
- **订座 > 160** 的航班在备注列标注「高客座航班」
- 一键**导出图片**（Canvas 2 倍高清，灰白配色表头、高客座标签醒目）

### 东上联日数据汇总（`/merge/`）

- 整合「航班数据统计」（03）与「航班运量汇总」（04）两个工具的输入
- 导入 FIOS 航班 Excel + 指挥长周报 **PDF**（自动读取其中的「起飞延误明细」）
- 输出**东上联 24 列**与**总表 23 列**两块数据
- 支持逐行复制 TSV（直接粘进共享文档）或导出 2 个 sheet 的 Excel

## 技术栈

- 纯 HTML / CSS / JS，**无后端、无构建步骤**
- [SheetJS](https://sheetjs.com/)（`libs/xlsx.full.min.js`）解析 / 导出 Excel
- [pdf.js](https://mozilla.github.io/pdf.js/)（`libs/pdfjs/pdf.min.mjs`）读取指挥长周报 PDF —— 仅 `/merge/` 使用
- html2canvas + jsPDF 生成日报 PDF —— 仅 `/daily-report/` 使用
- Canvas 2 倍分辨率绘制导出图片 —— `/schedule/`、`/kn-stats/`
- localStorage 本地持久化草稿 / 待办 —— `/schedule/`、`/todo/`、`/daily-report/`

## 设计系统

- `assets/site.css` 是全站唯一的设计系统来源，统一提供配色变量、按钮、表格、上传区、规则折叠面板等公共组件。
- 配色为**灰白苹果风**：主色 `#0071e3`，正文 `#1d1d1f`，次要文字 `#6e6e73` / `#86868b`，分隔线 `#d2d2d7` / `#e5e5ea`，底色 `#f5f5f7`。
- 每个工具页在自己的 `<style>` 里只写 `:root { --tool: 识别色 }`，用于卡片和页头的工具识别色，不影响整体灰白基调。
- 规则折叠面板（`.rules-panel`）已收敛为 `site.css` 中的唯一版本，各页不再重复定义。

## 部署

本地目录不是 git 仓库，两个站点各自发布。完整流程：

1. **同步**：把本目录内容 `rsync` 到 git 工作副本
   （`/Users/pangtouhema/WorkBuddy/2026-07-14-22-40-54/github-pages-prep/flight-tools/`），
   排除 `.DS_Store` / `.workbuddy-ai/` / `.wbapp_*.genie` / `.workbuddy/` / `.git/`
2. **推 GitHub**：`git add -A && git commit && git push origin main`
   → GitHub Pages 自动重新构建
   （走代理时 `git push` 经常被 502 打回，需 `GIT_HTTP_VERSION=1` 并循环重试十几次）
3. **推 WorkBuddy**：用 WorkBuddy 的「发布为应用」重新发布 **git 工作副本目录**
   （发布工具会把目录原样打包上传，所以工作副本里不能有 `.workbuddy-ai/` 这类内部文件）

> ⚠️ WorkBuddy 重新发布后**域名可能发生变化**，发布完要重新确认一次访问链接。
