## 重点功能说明

### 国际名单转化（`/manifest/`）

- 上传系统导出的国际航班旅客名单 Excel，自动生成海关上传模板
- **加密名单直接填密码即可**：系统导出的名单默认带密码，在「🔒 文件密码」框里填上密码就能直接转换，
  不需要先用别的工具去密码。
  - 文件没加密 → 密码框留空，走原来的路径（行为完全不变）
  - 文件加密但没填密码 → 该行标红，提示填密码
  - 密码填错 → 提示确认密码（区分大小写）
  - 解密全部在浏览器本地完成（`libs/xlsx-populate.min.js` 的 ECMA-376 Agile 解密，走浏览器自带 WebCrypto），
    那个库有 642 KB，**只在真的遇到加密文件时才加载**
  - ⚠️ 目前只支持 **ECMA-376 Agile** 这一种加密方式（Office 2010 以后的默认方式）。
    如果你的文件是更老的 Standard / RC4 加密，页面会明确提示不支持，需要先转成无密码版再上传。
- 转换规则：国籍 → 3 字码（含常见错别字修正）、性别 `1/2` → `M/F`、
  按航班号判定出入境（`MU261/751` 出境、`MU262/752` 入境）与往来地（马德里 / 罗马）
- **导出文件名**：按海关要求的格式自动命名 ——
  「航班订票数据上传模板」+ 航班日期 + 航班号，例如 `航班订票数据上传模板2025-04-27MU262.xlsx`。
  万一日期或航班号读不出来，退回 `原文件名_海关上传.xlsx`，不会导出半截名字
- 转换后展示预览表、汇总卡、国籍代码异常与已跳过记录的明细，逐条可核对

### 出港排班表（`/schedule/`）

- 上传 Excel，自动筛选出港航班（航班号自动清理 `#`、`&`）
- 计离 **0830 之前** 的航班自动剔除（属于前一组）
- 按计离自动分三段，分页切换查看：
  - 🌅 早上 `0830–1400`
  - ☀️ 下午 `1400–1830`
  - 🌙 晚上 `1830` 以后
- 备注列自动组合，顺序固定：**预推时间 → 特服（出港） → 航班调时**
- 负责栏多选（预设 5 人 + 自定义），导出图片用鲜艳实色标签直观区分
- 每行可「插入 / 删除」；插入的空行可直接编辑
- 登机口默认预填 `2`，只需补后两位
- 草稿：`存草稿` / `读取草稿` / `清空草稿`（存于浏览器 localStorage）
- 导出：当前页 Excel、全部 Excel（早 / 午 / 晚 三段各一表）、导出图片（灰白配色表头、负责人彩标）
- `一键清空` 整张表（带确认）

### KN航班出港统计（`/kn-stats/`）

- 上传 FIOS 系统导出的 Excel（.xls / .xlsx）
- 仅保留**出港**且航班号以 **KN** 开头的航班；删除机号为 `CNL` / `DEL` 的取消航班；自动清理航班号中的 `#`、`&`
- 在「计飞」右侧插入**截载时间**列（计飞 − 35 分钟）
- **出港订座** = 三舱位数相加（如 `0|0|158` → 158）
- 计飞 **1030（含）之前** 为早始发，在分界处插入汇总行「早始发人数：X」
- **订座 > 160** 的航班在备注列标注「高客座航班」
- 一键**导出图片**（Canvas 2 倍高清，灰白配色表头、高客座标签醒目）

### 东上联日数据汇总（`/merge/`）

- 整合「航班数据统计」与「航班运量汇总」两个工具（二者现已封存）的输入
- 导入 FIOS 航班 Excel + 指挥长周报 **PDF**（自动读取其中的「起飞延误明细」）
- 输出**东上联 24 列**与**总表 23 列**两块数据
- 支持逐行复制 TSV（直接粘进共享文档）或导出 2 个 sheet 的 Excel

### 早始发正常率测算（`/early-ontime/`）

把当月早始发的班数与机场同期数据放在一起，算清楚**还差多少班才能追平机场**。

- **三个对比主体**，共用同一个机场基准：
  - 中联航
  - 东上航 = 东航 + 上航
  - 东上联 = 中联航 + 东上航（**自动汇总**）
- **录入只要两个数** —— 我方和机场都**只填「总班数 + 延误班数」**：

  | 自动算出 | 公式 |
  |---|---|
  | 正常班数 | 总班数 − 延误班数 |
  | 正常率 | 正常班数 ÷ 总班数 |

  这两格是**只读派生格**，显示时**以正常率为主值**（放大、加粗、用工具色），
  正常班数作为小字附在下面。两格都填齐才开始测算；延误 > 总班数这类矛盾会就地提示。
- **机场区块两行**（都在 ② 区，同一块面板里）：
  - **当月累计** —— 总班数 / 延误班数 → 自动出正常班数与正常率
  - **全月预测** —— 全月总班数 / 全月延误班数 → 自动出**月末正常率**（追赶的目标基准）；
    留空或填错则沿用当月累计的正常率（派生格里直接显示「沿用当月」）
- **③ 本月进度**：本月已过天数 / 本月总天数。带一个**「读取今天」按钮** ——
  按今天日期填入，点了才填、仍可手改。
- **考核档位**，结果区可以**切换目标档位**（默认 T2 持平）：

  | 档位 | 含义 |
  |---|---|
  | T1 | 比机场低 1 个百分点 |
  | T2 | 与机场持平 |
  | T3 | 比机场高 1 个百分点 |

- **结果区第一屏就是「目标 + 追几班」** —— 每个主体一张追赶卡，两个数字并排：

  | 数字 | 含义 |
  |---|---|
  | **当前缺口** | 当前这批班里还差几班正常才够目标档（看现状） |
  | **剩余需正常** | 剩余航班还要保证几班正常，括号里给出占比（指导行动） |

  例如：`当前缺口 1 班` / `剩余需正常 86 班（96 班中占 89.58%）`。
  下面还有「三档对照」表（一眼看到三档各要追几班）和「现状对比」表（我方 vs 机场累计）。
- ⚠️ **两个基准不是同一个，别当 bug**：「比机场 ±X pt」恒用 **② 当月累计**的正常率；
  而「目标 / 缺口 / 追几班」用的是 **② 全月预测的月末正常率**（留空才退回当月累计）。
  因此**当前低于机场、但当前缺口是 0** 是正常的 —— 因为月末预测比现在低，T2 档反而已经够。
- **追不上告警**：如果剩余航班**全部正常也够不到目标档**，卡片会变红并说明
  「剩余 130 班即使全部正常，月末正常率最高也只有 84.85%」，同时告诉你**最高只能追到哪一档**。
- **全月预计班数**留空时，按「本月已过天数 ÷ 本月总天数」线性外推；填了就按填的算。
- **机场参考行**：因为机场数据**包含我方航班**，页面会额外给出「扣除东上联后，机场其他航司」
  的班数与正常率，便于判断差距到底来自哪里。
- 录入内容与选中的目标档位存 localStorage 草稿，刷新不丢。

## 技术栈

- 纯 HTML / CSS / JS，**无后端、无构建步骤**
- [SheetJS](https://sheetjs.com/)（`libs/xlsx.full.min.js`）解析 / 导出 Excel
- [xlsx-populate](https://github.com/dtjohnson/xlsx-populate)（`libs/xlsx-populate.min.js`）
  解密加密的 Excel —— 仅 `/manifest/` 使用，且**按需加载**（642 KB，只在遇到加密文件时才拉取）
- [pdf.js](https://mozilla.github.io/pdf.js/)（`libs/pdfjs/pdf.min.mjs`）读取指挥长周报 PDF —— 仅 `/merge/` 使用
- html2canvas + jsPDF 生成日报 PDF —— 仅 `/daily-report/` 使用
- Canvas 2 倍分辨率绘制导出图片 —— `/schedule/`、`/kn-stats/`
- localStorage 本地持久化草稿 / 待办 —— `/schedule/`、`/todo/`、`/daily-report/`

## 设计系统

- `assets/site.css` 是全站唯一的设计系统来源，统一提供配色变量、按钮、表格、上传区、规则折叠面板等公共组件。
- 配色为**灰白苹果风**：主色 `#0071e3`，正文 `#1d1d1f`，次要文字 `#6e6e73` / `#86868b`，分隔线 `#d2d2d7` / `#e5e5ea`，底色 `#f5f5f7`。
- 每个工具页在自己的 `<style>` 里只写 `:root { --tool: 识别色 }`，用于卡片和页头的工具识别色，不影响整体灰白基调。
- 规则折叠面板（`.rules-panel`）已收敛为 `site.css` 中的唯一版本，各页不再重复定义。

## 部署

只有 **GitHub Pages** 一个站点。本地目录不是 git 仓库，改完同步到 git 工作副本再推送：

1. **同步**：把本目录内容 `rsync` / `cp` 到 git 工作副本
